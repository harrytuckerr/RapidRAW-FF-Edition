## 3. Colour contract (fixed, not user-tunable)

Candidate: in-memory RGB32F has **linear transfer**, sRGB primaries `(0.64,0.33), (0.30,0.60), (0.15,0.06)`, D65 `(0.3127,0.3290)`. Never feed these samples to `prophoto_to_lab` or apply an sRGB inverse transfer.

Reference v1: classic TIFF, first and only main IFD, interleaved RGB unsigned 16-bit, no alpha, full range 0–65535. Normalize channels by 65535 without rounding to u8/f32. No filename/profile-description guessing, forced sRGB, “assign ProPhoto” override, OS display transform, auto-exposure fit or histogram matching.

**ICC candidate subset, pending H2b3 release:** v2/v4, `acsp`, class `mntr`, data space `RGB `, PCS `XYZ `; D50 header and `wtpt` encoding/white-consistency checks must first be frozen from the actual bytes and review below. No one-LSB gate is authorized. Support `rXYZ/gXYZ/bXYZ` XYZ-type matrix columns plus each channel's `curv` count 0 (identity) or count 1 (u8Fixed8 exponent, strictly positive). Reject table curves, `para`, other classes, LUT/multi-process transform tags (`A2B*`, `B2A*`, `D2B*`, `B2D*`), non-D50 media white and unsupported HDR extensions. This is a small matrix/gamma subset, not a general ICC engine. Bounds-check header size, tag table arithmetic, payload ranges/types/counts; reject duplicate signatures, truncated data and partial overlaps; exact shared payload ranges are legal. Require a finite nonsingular matrix. Every harness inverse is fallible; never copy `delta_e.rs:186–188` or renderer identity-on-singularity fallbacks (F8). Ignore only non-transform descriptive tags; report their signatures. Do not silently prefer matrix tags when a competing transform exists.

Evaluate each TRC from the actual profile bytes, then multiply matrix columns into relative PCS XYZ. The matrix already maps to D50 PCS: do **not** apply `chad` again. If present, parse/validate `chad` structure and finite values and report it, but do not use it in this relative transform. Apply Bradford **PCS D50 `[0.9642,1,0.8249]` → Wc** once before the existing Lab helper. These two rounded D50 definitions are intentionally distinguished. Do not normalize colourant rows or substitute the renderer's ProPhoto matrix for ICC values.

Adobe ProPhoto TIFF must pass this structural/identity contract; actual exported ICC shape remains unverified. A gamma near 1.8 in a `curv` is decoded as its exact stored exponent, not idealized 1.8, a ROMM toe curve, sRGB or linear. Unsupported real ICC shape is a precise blocker for the next slice, not permission to broaden this parser opportunistically. [ICC matrix/TRC model and curve encoding](https://www.color.org/specifications/ICC.1-2022-05.pdf), §§8.4.3, 10.6, F.3; [ICC v2 specification](https://archive.color.org/files/ICC34.pdf). [ROMM specification](https://www.color.org/chardata/rgb/ROMMRGB.pdf) separately defines a transfer with a low-end segment; its name alone cannot identify an exported ICC's TRC.

**F3 adjudication — do not normalize a suspect matrix:** [ICC.1:2022](https://www.color.org/specifications/ICC.1-2022-05.pdf) §7.2.16 specifies the header white by rounding to four decimals; §9.2.36 makes display `wtpt` the PCS illuminant; F.3 specifies TRC→matrix device-to-PCS. These provisions do not state the review's one-LSB column-sum inequality. The intended neutral-white check is on the decoded matrix's `[1,1,1]` response for the supported unit-endpoint TRCs, not a correction of its coefficients.

Independent quantization analysis: let q=1/65536. **If** three exact colourants sum to an exact white and all four quantities are independently rounded to nearest fixed-point, the triangle bound on `sum(encoded colourants)-encoded white` is `(3/2+1/2)q=2q`, not q. Other upstream matrix rounding/adaptation or differing white definitions require their own budget; 2q is a conditional arithmetic bound, **not a universal ICC conformance rule**. ICC's [matrix-entry technical note](https://archive.color.org/files/v4_matrix_entries.pdf), pp2–3, demonstrates multiply-by-65536/nearest-integer encoding, but concerns LUT matrices and does not establish a colourant-sum tolerance. Four-decimal header rounding also is not equivalent to “within one fixed-point unit”.

Decision: **H2b3 stays pending** until one controlled Adobe reference supplies exact header/`wtpt`/colourants/`chad`/TRCs, and a reviewer freezes a version-specific supported invariant and justified bound with boundary fixtures. Record decoded sums/residuals and reject unsupported structure/semantics; never row-normalize, adapt from the column sum, change Lab white or invent a looser bound to force acceptance. No guessed `para`/LUT/class broadening. H2b1–2 can proceed on explicit assignments without these bytes.

Bradford: `B=[[.8951,.2664,-.1614],[-.7502,1.7135,.0367],[.0389,-.0685,1.0296]]`; `A=inv(B)*diag((B*Wdst)/(B*Wsrc))*B`. No gamut mapping, black-point compensation or integer PCS quantization. [W3C conversion reference](https://www.w3.org/TR/2026/CRD-css-color-4-20261009/#color-conversion-code) supplies independent matrix/adaptation examples; this harness does not adopt CSS gamut mapping.

Extended range: retain finite negative and >1 candidate channels through matrix, adaptation and the existing piecewise Lab function (linear branch below `(6/29)^3`, including negatives). Never clamp to reference gamut or to [0,1]. Record per-side/channel min/max, counts outside [0,1], XYZ negatives and Lab L outside [0,100]. Finite extended-Lab ΔE is a diagnostic extrapolation, not HDR perceptual acceptance. Any nonfinite RGB, XYZ, Lab or ΔE at any pixel, even an excluded pixel, fails the case. Check arithmetic output finiteness before sorting/serialization. Production Look clamping remains visible as a limitation; the harness cannot recover discarded values.

## 5. Metrics, masks and status

Compute ΔE for every pixel after geometry/finite validation. Default `none` includes all pixels. Optional reference-only mask: shadow iff **reference adapted XYZ Y < 0.001**; ceiling iff **any original reference u16 channel ==65535**. The latter is an observable channel-ceiling proxy, not proof of sensor clipping. Do not retain the old “any linear ProPhoto channel >0.999” rule. Never exclude on candidate darkness/clipping or on measured ΔE. Expected mask parameters/counts/SHA are frozen independently from the pinned reference. During the pixel pass derive each mask byte from the reference before evaluating that candidate pixel; compare final counts/hash before accepting metrics. No candidate information enters the mask; mismatches fail.

Partition into `included`, `shadow_only`, `ceiling_only`, `both`; `excluded_union=shadow_only+ceiling_only+both`, and `total=included+excluded_union`. Also expose inclusive shadow/ceiling counts and overlap explicitly. Hash a row-major byte-per-pixel mask (bit0 shadow, bit1 ceiling). Report all-pixel, included, each disjoint excluded group's and excluded-union mean/p95/max/count using the bounded storage policy below. Empty diagnostic groups have metrics `null`, never 0. Any empty primary sample, zero-size image, mask-length mismatch, duplicate case, NaN/Inf, overflow or serialization failure is a hard failure. Excluded pixels still undergo finite checks and have separate measured statistics.

Per-case acceptance uses strict **mean <2, p95 <3, max <5**, no epsilon. p95 is nearest-rank `sorted[ceil(.95*N)-1]`; report this definition. Finite nonnegative samples, positive count and valid count accounting are prerequisites for threshold functions, including GPU parity helper; reject fabricated invalid stats. Add fallible stats API / update existing callers within owned files; do not leave an empty-zero passing helper exported as an alternate path. Do not change CIEDE2000 or renderer math to achieve thresholds.

Aggregate by pooling actual included pixel ΔE samples across cases, never averaging means/p95/max. Report per-case and aggregate metrics; retain failing cases. Run Pass requires every requested case to execute and pass **and** pooled thresholds to pass. Aggregate cannot hide an individual failure. If any case cannot produce samples, label aggregate `partial` with contributing/requested case counts; run remains Fail. Equal-to-threshold fails. `synthetic_harness` Pass means comparator evidence only; no Adobe or real-camera claim.

**F4 capacity/allocation policy (binding before pixel implementation):** v1 accepts at most 80,000,000 pixels per case **and in the sum of declared case dimensions**; dimensions/product/sum use checked integer arithmetic. This is a capacity ceiling, not a new fidelity tolerance. Preflight every reference header and declared candidate size before rendering; actual dimensions must match. Limit each RAW or reference file to 512 MiB, DCP/Look to 128 MiB each, ICC to 16 MiB, manifest and final report to 8 MiB each. Above-limit, checked-size overflow, fallible reserve failure, or decoder resource-limit error => stable `RESOURCE`, exit2; no resizing/subsampling/approximate quantiles.

For one case N pixels, retain candidate `12N` bytes (RGB32F), decoded reference `6N` (RGB16), and one `Sample { de:f64, category:u8 }` record per pixel (charge `size_of::<Sample>()*N`, normally `16N`). Compute RGB→XYZ→Lab→ΔE **once per pixel** with stack triples; update finite/range/count/sum/min/max scalars and streaming mask/output hashes. Store no full XYZ/Lab image, mask vector, duplicate ΔE image or per-pixel JSON. Retaining excluded ΔE records is necessary for the promised exact excluded-group p95: the review's included-only storage would silently drop that metric. In-place unstable sort by ΔE then scan category flags gives exact p95 for all/disjoint/included/union groups without scratch vectors. Append only included ΔE to one global f64 pool; global capacity is the declared sum S, at most `8S` bytes. Sort that pool in place at run end; no cloning/concatenation copies. This preserves pooled quantiles and per-case failures.

Preflight a **2 GiB managed-memory reservation ceiling** using `12N+6N+size_of::<Sample>()*N+8S+B+512 MiB+64 MiB`, where B is the sum of byte-buffer capacities for the current RAW/reference/DCP/Look (ICC borrows the reference buffer; charge any unavoidable ICC copy explicitly). The 512 MiB reserve covers reference decoder workspace; set image decoder `Limits.max_alloc` to that maximum and validate dimensions before decode. The 64 MiB reserve covers bounded manifest/report/control buffers. Use `try_reserve_exact` before each owned Vec allocation and check returned capacity against the budget; never unbounded `collect`, geometric growth, a full image `clone` or allocating stable sort in the comparator. Free per-case arrays/buffers before the next case; only global included pool plus bounded report summaries persist. Fail before allocating if the budget is exceeded even when pixel count alone fits. Add capacity tests using size plans/injected allocation failure, not actual multi-GiB allocations.

This bounds **comparator-managed** storage, not process RSS or all rawler/production-renderer internals. Metadata-decode and parsed-profile/Look preflight buffers must be dropped before production rendering; pre-existing rawler/asset-parser/pipeline allocations cannot be made universally fallible without out-of-scope changes. Record this limit, measure peak memory when real rendering is assigned, and treat a subprocess abort as failed execution/no acceptance, never fabricate a `RESOURCE` report after process death. H2b1's in-file stats helper must likewise bound/check its own sample-copy allocation; H2b5's one-pass engine must not call it in a way that creates a second full-size copy.

Machine-readable report (`schema_version=1`) contains run/case IDs, source/binary/manifest/input/output hashes, observed settings/ICC/geometry, time breakdown, counts/mask hash/metrics, thresholds, `status: "Pass"|"Fail"|"Not exercised"`, and structured `errors:[{code,stage,case_id,asset_role,detail}]`.
