## 2. H2b interface and execution

New invocation: `validate_dcp compare --manifest <run.json> --report <new-report.json>`. Exactly these flags, once each; missing/duplicate/unknown arguments fail. Old ambiguous `compare --raw ... --reference ...` fails with migration guidance. Existing `render`/`self-test` remain available; neither constitutes acceptance.

Manifest contains a nonempty ordered list of uniquely named cases. For every case, validate schema/assets/identity/encoding/geometry, then call the same actual CPU pipeline used by `render`, holding candidate RGB32F in memory. Factor registry construction into a helper inside the CLI; do not replace the pipeline with synthetic swatches or a separate renderer. Process cases sequentially. Continue after a case failure to report other cases; never omit a requested case. No network, reference generation, fallback profile or implicit settings correction.

Candidate route is fixed to `cpu_profile_pre_adjustments_v1`: `fast=false`, `highlight=2.5`, `linear_mode="auto"`, As Shot WB, profile/base + optional native Look, Amount 0–200 inclusive. Reject other requested controls in v1 rather than record unexecuted settings. Without a Look, require amount 100 as an inert canonical value. This harness restriction does not change production Amount semantics. Camera/profile/Look identity must agree with parsed assets and the real pipeline. For recorded WB/camera verification, decode RAW metadata read-only using locked rawler APIs and the same existing multi-exposure neutralization helper; no new public production API. Compare expected first-three gains/neutral with fixed abs+relative tolerance 1e-6 (record it); the unused fourth RGBE slot may be NaN and is not pixel data. Record observed values.

A controlled Adobe export is a full Adobe rendering, not proof of an isolated DCP stage. Record that asymmetry. The resulting per-case measurements test the declared CPU-vs-Adobe target; mismatches may include demosaic, baseline, tone and colour-management differences. Never infer full app export fidelity from a passing profile-boundary case. Synthetic tests are labelled synthetic and cannot satisfy Adobe provenance.

## 3. Colour contract (fixed, not user-tunable)

Common space: relative CIE Lab, CIE 1931 2° observer, reference white `Wc = [0.9642956764, 1.0, 0.8251046025]` (existing DNG D50 convention). Reuse existing `xyz_to_lab` and `cie_de2000`, with kL=kC=kH=1. All comparator arithmetic after f32 input widening uses f64.

Candidate: in-memory RGB32F has **linear transfer**, sRGB primaries `(0.64,0.33), (0.30,0.60), (0.15,0.06)`, D65 `(0.3127,0.3290)`. Derive the RGB→XYZ matrix from these published chromaticities and unit-white normalization independently of `render.rs`; then linear Bradford D65→Wc. Never feed these samples to `prophoto_to_lab` or apply an sRGB inverse transfer.

Reference v1: classic TIFF, first and only main IFD, interleaved RGB unsigned 16-bit, no alpha, full range 0–65535. Normalize channels by 65535 without rounding to u8/f32. Require an embedded ICC whose SHA-256 equals the manifest's pinned expected ICC. Decode samples without automatic colour conversion. Reject untagged references, malformed/mismatching ICC, CMYK/Lab/gray, float/HDR reference TIFF, unsupported sample organization and multiple main images. v1 may reject BigTIFF. No filename/profile-description guessing, forced sRGB, “assign ProPhoto” override, OS display transform, auto-exposure fit or histogram matching.

Bounded ICC reader: v2/v4, `acsp`, class `mntr`, data space `RGB `, PCS `XYZ `; require D50 header illuminant and D50 `wtpt` within one s15Fixed16 quantization unit of `[0.9642,1,0.8249]`. Support `rXYZ/gXYZ/bXYZ` XYZ-type matrix columns plus each channel's `curv` count 0 (identity) or count 1 (u8Fixed8 exponent, strictly positive). Reject table curves, `para`, other classes, LUT/multi-process transform tags (`A2B*`, `B2A*`, `D2B*`, `B2D*`), non-D50 media white and unsupported HDR extensions. This is a small matrix/gamma subset, not a general ICC engine. Bounds-check header size, tag table arithmetic, payload ranges/types/counts; reject duplicate signatures, truncated data and partial overlaps; exact shared payload ranges are legal. Require a finite nonsingular matrix. Ignore only non-transform descriptive tags; report their signatures. Do not silently prefer matrix tags when a competing transform exists.

Evaluate each TRC from the actual profile bytes, then multiply matrix columns into relative PCS XYZ. The matrix already maps to D50 PCS: do **not** apply `chad` again. If present, parse/validate `chad` structure and finite values and report it, but do not use it in this relative transform. Apply Bradford **PCS D50 `[0.9642,1,0.8249]` → Wc** once before the existing Lab helper. These two rounded D50 definitions are intentionally distinguished. Do not normalize colourant rows or substitute the renderer's ProPhoto matrix for ICC values.

Adobe ProPhoto TIFF must pass this structural/identity contract; actual exported ICC shape remains unverified. A gamma near 1.8 in a `curv` is decoded as its exact stored exponent, not idealized 1.8, a ROMM toe curve, sRGB or linear. Unsupported real ICC shape is a precise blocker for the next slice, not permission to broaden this parser opportunistically. [ICC matrix/TRC model and curve encoding](https://www.color.org/specifications/ICC.1-2022-05.pdf), §§8.4.3, 10.6, F.3; [ICC v2 specification](https://archive.color.org/files/ICC34.pdf). [ROMM specification](https://www.color.org/chardata/rgb/ROMMRGB.pdf) separately defines a transfer with a low-end segment; its name alone cannot identify an exported ICC's TRC.

Bradford: `B=[[.8951,.2664,-.1614],[-.7502,1.7135,.0367],[.0389,-.0685,1.0296]]`; `A=inv(B)*diag((B*Wdst)/(B*Wsrc))*B`. No gamut mapping, black-point compensation or integer PCS quantization. [W3C conversion reference](https://www.w3.org/TR/2026/CRD-css-color-4-20261009/#color-conversion-code) supplies independent matrix/adaptation examples; this harness does not adopt CSS gamut mapping.

Extended range: retain finite negative and >1 candidate channels through matrix, adaptation and the existing piecewise Lab function (linear branch below `(6/29)^3`, including negatives). Never clamp to reference gamut or to [0,1]. Record per-side/channel min/max, counts outside [0,1], XYZ negatives and Lab L outside [0,100]. Finite extended-Lab ΔE is a diagnostic extrapolation, not HDR perceptual acceptance. Any nonfinite RGB, XYZ, Lab or ΔE at any pixel, even an excluded pixel, fails the case. Check arithmetic output finiteness before sorting/serialization. Production Look clamping remains visible as a limitation; the harness cannot recover discarded values.

## 5. Metrics, masks and status

Compute ΔE for every pixel after geometry/finite validation. Default `none` includes all pixels. Optional reference-only mask: shadow iff **reference adapted XYZ Y < 0.001**; ceiling iff **any original reference u16 channel ==65535**. The latter is an observable channel-ceiling proxy, not proof of sensor clipping. Do not retain the old “any linear ProPhoto channel >0.999” rule. Never exclude on candidate darkness/clipping or on measured ΔE. Freeze mask parameters/counts/SHA before candidate comparison, derived only from the pinned reference; mismatches fail.

Partition into `included`, `shadow_only`, `ceiling_only`, `both`; `excluded_union=shadow_only+ceiling_only+both`, and `total=included+excluded_union`. Also expose inclusive shadow/ceiling counts and overlap explicitly. Hash a row-major byte-per-pixel mask (bit0 shadow, bit1 ceiling). Report all-pixel, included, each disjoint excluded group's and excluded-union mean/p95/max/count. Empty diagnostic groups have metrics `null`, never 0. Any empty primary sample, zero-size image, mask-length mismatch, duplicate case, NaN/Inf, overflow or serialization failure is a hard failure. Excluded pixels still undergo finite checks and have separate measured statistics.

Per-case acceptance uses strict **mean <2, p95 <3, max <5**, no epsilon. p95 is nearest-rank `sorted[ceil(.95*N)-1]`; report this definition. Finite nonnegative samples, positive count and valid count accounting are prerequisites for threshold functions, including GPU parity helper; reject fabricated invalid stats. Add fallible stats API / update existing callers within owned files; do not leave an empty-zero passing helper exported as an alternate path. Do not change CIEDE2000 or renderer math to achieve thresholds.

Aggregate by pooling actual included pixel ΔE samples across cases, never averaging means/p95/max. Report per-case and aggregate metrics; retain failing cases. Run Pass requires every requested case to execute and pass **and** pooled thresholds to pass. Aggregate cannot hide an individual failure. If any case cannot produce samples, label aggregate `partial` with contributing/requested case counts; run remains Fail. Equal-to-threshold fails. `synthetic_harness` Pass means comparator evidence only; no Adobe or real-camera claim.

Machine-readable report (`schema_version=1`) contains run/case IDs, source/binary/manifest/input/output hashes, observed settings/ICC/geometry, time breakdown, counts/mask hash/metrics, thresholds, `status: "Pass"|"Fail"|"Not exercised"`, and structured `errors:[{code,stage,case_id,asset_role,detail}]`. For candidate output hash, hash ASCII `RRH2RGBF32V1` followed by one zero byte, width/height as u32 little-endian, then row-major little-endian f32 RGB bytes; record layout/version, not an unstable in-memory struct. Optional saved diagnostic TIFF has a separate file hash and explicit linear-sRGB sidecar. No commercial pixel dumps in Git.

Exit 0 = every requested case Pass. Exit 1 = measured threshold failure. Exit 2 = usage/schema/input/identity/encoding/geometry/nonfinite/internal/report-write failure (wins over 1 when mixed). Exit 3 = explicitly requested unsupported acceptance scope (`preview`, `export`, `thumbnail`, `upstream`, GPU or HDR), with Not exercised reason. Missing required assets in an invoked compare run are **Fail / exit 2**, not skips. Empty manifest is Fail / exit 2. Never print NaN/Infinity as JSON or rely on serializer conversion to null. Write report atomically to a new path; failure to write cannot exit 0. Emit a minimal structured error to stderr if the report path is unusable; logs stay off JSON stdout.

Minimum stable error codes: `USAGE`, `MANIFEST_INVALID`, `EMPTY_RUN`, `INPUT_MISSING`, `HASH_MISMATCH`, `BINARY_MISMATCH`, `PROFILE_INVALID`, `PROFILE_IDENTITY_MISMATCH`, `LOOK_INVALID`, `PAIRING_OR_CAMERA_MISMATCH`, `RENDER_FAILED`, `ENCODING_UNSUPPORTED`, `ICC_MISSING_OR_UNREADABLE`, `ICC_INVALID`, `ICC_HASH_MISMATCH`, `GEOMETRY_MISMATCH`, `ORIENTATION_UNSUPPORTED`, `SETTINGS_UNSUPPORTED`, `NONFINITE_SAMPLE`, `EMPTY_SAMPLE`, `MASK_INVALID`, `THRESHOLD_EXCEEDED`, `SCOPE_NOT_IMPLEMENTED`, `REPORT_WRITE_FAILED`. Keep raw production error text as detail; do not depend on fragile substring parsing for safety decisions.

## 6. Independent tests and failure injection

1. Independent RGB→XYZ→Lab known answers: black, D65 white mapped to Wc/Lab `[100,0,0]`, linear gray 0.18 (`L≈49.49610761,a=b=0`), unequal-channel primaries and chromatic samples. Include negative and >1 candidate channels to expose clipping, and a D65/D50 case that fails if adaptation is omitted/reversed/doubled.
2. Synthetic ICC assembled from documented bytes: count-0 identity, count-1 gamma 2 (encoded 512), and non-integer u8Fixed8 gamma. At input 0.5 gamma 2 gives 0.25, not sqrt(0.5); neutral linear 0.25 gives `L≈57.07542089`. Include unequal channels and a non-symmetric matrix to catch transpose errors. Prove tiny PCS-D50→Wc adaptation, and no double `chad`. Match independent known Lab within 1e-6 for f64 analytic fixtures; use separately justified ≤0.005 Lab/component for u16 quantization fixtures, never the product ΔE threshold as a conversion-unit tolerance.
3. Independently known-good pair through the **same comparison core** (candidate linear-sRGB values versus independently encoded RGB16+ICC values) passes. Deliberately change one included pixel sufficiently that max ΔE >5: comparison and report Fail. This is comparator evidence, not a mocked claim that a real image route ran. One-pixel threshold exceedance must not disappear into mean/p95 pooling.
4. Reassign wrong ICC while holding expected ICC SHA fixed → ICC/hash failure; change expected tag to a structurally supported but wrong transfer in a test-specific manifest → colour mismatch on known samples. Missing ICC, unknown transfer, LUT-profile, wrong matrix type, duplicate/truncated/overflowing ICC tags, singular matrix and malformed TIFF metadata fail. An attacker/operator who rewrites all provenance and pixels consistently cannot be detected from colour numbers alone; reference custody remains external evidence.
5. Empty arrays/images, all-excluded samples, unequal mask lengths, overlapping shadow/ceiling, NaN/Inf in included **and excluded** pixels, huge finite values causing conversion overflow, exact thresholds, 1/19/20/21-sample p95 and unequal-sized-case aggregation. 6. CLI/process regressions: missing reference, missing DCP, invalid Look, mismatched base/camera, changed source asset/ICC hash, settings mismatch, bad orientation/dimensions, unwritable/existing report target, duplicate/unknown flags and unsupported route. Assert exit code + report code/status; no fake pipeline success.
