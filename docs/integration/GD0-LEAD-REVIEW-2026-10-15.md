**Accept for bounded pure-model implementation, not provider, authentication, security or product acceptance.** The amended scope includes settings, saved edits, named checkpoints, presets and legitimately user-imported profile libraries across desktop and Android, with originals downloaded when needed. Profile selection, compatible base/Look pairing, exact bytes/identities and Amount remain separate from adjustment presets. No commercial bytes enter this source review.

The design keeps native credentials and device paths out of shared state, separates app data from visible photo transfers, retains independent account generations, uses immutable revision ancestry rather than timestamp winners, and distinguishes local durability from upload acknowledgement. Dirty state, profile collisions, missing dependencies and incompatible rendering context stay explicit. The current native capture-flag loss is a separate prerequisite; corrupt legacy data is not enrolled from fallback defaults.

Google's current official app-data and scope documentation was independently opened by the lead: configuration storage and the narrow additional scope are documented. App-specific profile-library suitability, cross-native client visibility, policy/retention eligibility, actual credentials, API37 background behavior and secure-store choices remain unresolved gates. No live request, login, account mutation or provider experiment was performed by this review. A source contract cannot establish those outcomes.

Implementation is reduced further than the contract's first combined slice: **GD1a1 only** defines strict bounded revision-envelope primitives and explicit `Unvalidated` payload applicability in two new module files. Graph/conflict/ack algorithms follow in a separate slice after that API freezes. No filesystem, network, OAuth, UI, renderer or application to current saved state is permitted in GD1a1. Native registration remains lead-owned. This avoids giving a worker the complete sync product at once.

The codec must remain a real prerequisite before data application or upload: an opaque JSON payload passing envelope validation must never be labelled portable, safe to publish or Ready. Identity syntax is not authenticated account ownership. Exact received bytes and hashes remain distinct from reserialized semantics. Unknown versions, malformed/duplicate keys, non-finite values and exceeded limits fail explicitly, without defaults or truncation.
