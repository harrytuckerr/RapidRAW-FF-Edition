## User intent and design contract

The photographer chooses a camera-correct base profile, optionally adds a Cobalt image Look, then applies adjustment presets and edits sliders on top. Both desktop and Android use the same UI and state contracts. A Cobalt image Look remains part of profile rendering; it must not be relabelled as an ordinary exposure/colour/effects preset.

This is an existing compact photo editor, not a new design system. Domain: camera body, base profile, image Look, exposure, colour, effects, preset intensity, RAW development. Colour world: neutral editing canvas, charcoal panels, grey controls, white captions, existing accent; retain semantic theme tokens to avoid biasing image judgement. Signature: the current base and optional Look remain visible as the foundation beneath adjustment presets. Avoid unlabeled import icons, treating all XMPs as interchangeable, and replacing profile state as a side effect of an ordinary preset. Use explicit action labels and a short layering explanation.

The photo remains the focal point; controls stay compact with existing type, surfaces and 4px spacing conventions. Use existing button/text/dropdown patterns, visible focus and at least 44px touch targets. Retain the neutral surfaces and existing theme; no new palette or typography. These decisions apply to each changed component.
